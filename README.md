# SF Form sender

Универсальный перехватчик форм для WordPress. Принимает содержимое любой
отмеченной формы, отправляет письмо, сохраняет заявку в базу данных сайта,
прикладывает рекламные метки из GET и защищает форму от роботов.

Вебмастеру достаточно одного атрибута в теге формы — остального в шаблоне
может не быть вовсе:

```html
<form method="post" sf-form-sender-interceptor>
    <input type="text" name="name" required>
    <input type="email" name="email">
    <button type="submit">Отправить</button>
</form>
```

Контейнеры уведомлений, капчу, поле-приманку и служебные поля плагин добавит
сам. Если вебмастер разместил контейнеры сам — плагин возьмёт его, вместе с
его оформлением.

* **Скачать:** установочный архив приложен к каждому
  [GitHub Release](../../releases/latest); в репозиторий он намеренно не
  коммитится.
* **Плагин:** `sf-form-sender/` — только этот каталог и уезжает в поставку.
* **Документация для вебмастера:** вкладка *SF Form sender → Настройки →
  Документация* в админке и `sf-form-sender/readme.txt`.
* **Тесты:** `tests/` — см. `TEST-REPORT.md`.
* **Выпуск версии:** `BUILD.md`.
* **Правила, которым следует каждая правка:** `CLAUDE.md`.

## Требования

* WordPress 7.0 или новее
* PHP 7.4 или новее
* Расширения `mbstring` и `json`. Для сверки содержимого файлов пригодятся
  `fileinfo` и `exif` — без них проверка мягче, но плагин работает.

Внешних зависимостей у плагина нет: ни composer, ни npm, ни обращений к чужим
серверам — кроме проверки капчи, и то лишь когда она включена.

## Быстрый старт

1. Скопируйте `sf-form-sender/` в `wp-content/plugins/` или установите архив
   из GitHub Release через *Плагины → Добавить новый → Загрузить плагин*.
2. Активируйте. При активации создаются четыре таблицы, заполняются настройки,
   тексты уведомлений записываются на языке сайта, а каталог загрузок
   закрывается от выполнения файлов.
3. Заполните *SF Form sender → Настройки → Основное → Кому отправлять письма*.
   Пустое поле означает адрес администратора из общих настроек WordPress.
4. Добавьте атрибут `sf-form-sender-interceptor` в тег нужной формы.

Настройки разложены по шести вкладкам: Основное, Антиспам, SMTP, Phpmail,
Уведомления, Документация. Заявки — на отдельной странице, с настраиваемым
составом и порядком колонок. Язык интерфейса переключается в правом верхнем
углу; по умолчанию — язык сайта.

## Как это устроено

Перехват живёт **в браузере**, а не в PHP: скрипт находит формы по атрибуту,
раздаёт им имена, дописывает недостающее и берёт на себя отправку. Поэтому он
одинаково работает с формами из шаблона, с формами в модальных окнах и на
закешированных страницах, где PHP до посетителя не доходит вовсе.

Проверку заполнения плагин **не трогает**: незаполненное `required` обрабатывает
браузер, собственная проверка вебмастера вешается на отменяемое событие
`sf-form-sender:before-send`. Свои уведомления плагин показывает только про то,
что задано в его настройках.

Заявки лежат в четырёх таблицах: словарь встреченных имён полей, значения,
сами заявки и файлы. Широкой таблицы с фиксированными колонками быть не может —
поле с именем отправителя на разных сайтах называется `name`, `nombre`, `nom`,
`nome`, `isim`.

Подробности решений — в `CLAUDE.md`.

## Запуск тестов

```bash
php tests/test-plugin.php        # 205 проверок, нужен php-sqlite3, gd, exif
python3 tests/test-front.py      # 58 проверок, нужен playwright и chromium
python3 tools/build-languages.py # словари собраны и ничего не потеряно
php build-zip.php                # архив собирается и он полный
```

CI гоняет то же самое на PHP 7.4 и 8.4, плюс дымовую проверку на настоящем
WordPress: активация, таблицы, страницы админки, словари.

## Выпуск версии

Поднять версию в трёх местах, дописать изменения в `readme.txt`, запушить —
и либо запустить **Actions → Release → Run workflow**, либо запушить тег
`vX.Y.Z`. Дальше всё делает workflow. См. `BUILD.md`.
